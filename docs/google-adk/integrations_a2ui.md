# A2UI — Agent-to-UI for ADK[¶](#a2ui-agent-to-ui-for-adk "Permanent link")

Supported in ADKPython

A2UI lets your agent generate **real UI** — cards, forms, charts, tables — not just text. Your agent outputs structured JSON, and a renderer on the client turns it into interactive components.

It's transport-agnostic: A2UI payloads work over A2A, MCP, REST, WebSockets, or any other protocol. The agent describes *what* to show; the client decides *how* to render it.

Learn more about A2UI

[a2ui.org](https://a2ui.org/) has the full specification, component gallery, catalog reference, and renderer documentation.

## Quickstart[¶](#quickstart "Permanent link")

### Install the SDK[¶](#install-the-sdk "Permanent link")

`[](#__codelineno-0-1)pip install a2ui-agent-sdk`

### 1\. Set up the Schema Manager[¶](#1-set-up-the-schema-manager "Permanent link")

The `A2uiSchemaManager` loads component catalogs and generates system prompts that teach the LLM how to produce valid A2UI JSON.

`[](#__codelineno-1-1)from a2ui.core.schema.manager import A2uiSchemaManager [](#__codelineno-1-2)from a2ui.basic_catalog.provider import BasicCatalog [](#__codelineno-1-3)[](#__codelineno-1-4)schema_manager = A2uiSchemaManager(     [](#__codelineno-1-5)    catalogs=[        [](#__codelineno-1-6)        BasicCatalog.get_config(            [](#__codelineno-1-7)            examples_path="examples",        [](#__codelineno-1-8)        ),    [](#__codelineno-1-9)    ], [](#__codelineno-1-10))`

Note

The schema manager will automatically detect the A2UI version from incoming client requests. You can also set a version explicitly by passing `version=VERSION_0_9` if needed.

Tip

If you omit the `catalogs` parameter, the schema manager uses the [Basic Catalog](https://a2ui.org/concepts/catalogs/) maintained by the A2UI team, which includes common components like Text, Card, Button, Image, and more. You can also create [custom catalogs](#custom-catalogs) with domain-specific components, or mix the basic catalog with your own — see [Advanced patterns](#advanced-patterns) below.

### 2\. Generate the system prompt[¶](#2-generate-the-system-prompt "Permanent link")

The `generate_system_prompt` method combines your agent's role description with the A2UI JSON schema and few-shot examples, so the LLM knows exactly how to format its output.

`[](#__codelineno-2-1)instruction = schema_manager.generate_system_prompt(     [](#__codelineno-2-2)    role_description="You are a helpful assistant that presents information with rich UI.",    [](#__codelineno-2-3)    workflow_description="Analyze the user's request and return structured UI when appropriate.",    [](#__codelineno-2-4)    ui_description="Use cards for summaries, tables for comparisons, and forms for user input.",    [](#__codelineno-2-5)    include_schema=True,    [](#__codelineno-2-6)    include_examples=True,    [](#__codelineno-2-7)    allowed_components=["Heading", "Text", "Card", "Button", "Table"], [](#__codelineno-2-8))`

### 3\. Create your ADK agent[¶](#3-create-your-adk-agent "Permanent link")

Use the generated instruction as the agent's system prompt:

`[](#__codelineno-3-1)from google.adk.agents.llm_agent import LlmAgent [](#__codelineno-3-2)[](#__codelineno-3-3)agent = LlmAgent(     [](#__codelineno-3-4)    model="gemini-flash-latest",    [](#__codelineno-3-5)    name="ui_agent",    [](#__codelineno-3-6)    description="An agent that generates rich UI responses.",    [](#__codelineno-3-7)    instruction=instruction, [](#__codelineno-3-8))`

### 4\. Validate and stream A2UI output[¶](#4-validate-and-stream-a2ui-output "Permanent link")

Always validate the LLM's JSON output before sending it to the client. The SDK provides parsing, fixing, and validation utilities:

`[](#__codelineno-4-1)from a2ui.core.parser.parser import parse_response [](#__codelineno-4-2)from a2ui.a2a import parse_response_to_parts [](#__codelineno-4-3)[](#__codelineno-4-4)# Get the active catalog's validator [](#__codelineno-4-5)selected_catalog = schema_manager.get_selected_catalog() [](#__codelineno-4-6)[](#__codelineno-4-7)# Option A: Manual parse + validate [](#__codelineno-4-8)response_parts = parse_response(llm_output_text) [](#__codelineno-4-9)for part in response_parts:     [](#__codelineno-4-10)    if part.a2ui_json:        [](#__codelineno-4-11)        selected_catalog.validator.validate(part.a2ui_json) [](#__codelineno-4-12)[](#__codelineno-4-13)# Option B: One-liner that returns A2A Parts [](#__codelineno-4-14)parts = parse_response_to_parts(     [](#__codelineno-4-15)    llm_output_text,    [](#__codelineno-4-16)    validator=selected_catalog.validator,    [](#__codelineno-4-17)    fallback_text="Here's what I found.", [](#__codelineno-4-18))`

A2UI payloads are wrapped in A2A `DataPart` with the MIME type `application/json+a2ui` so renderers can identify them:

`[](#__codelineno-5-1)from a2ui.a2a import create_a2ui_part [](#__codelineno-5-2)[](#__codelineno-5-3)part = create_a2ui_part({"type": "Card", "props": {"title": "Hello"}}) [](#__codelineno-5-4)# → DataPart(data={...}, metadata={"mimeType": "application/json+a2ui"})`

## Advanced patterns[¶](#advanced-patterns "Permanent link")

### Dynamic catalogs[¶](#dynamic-catalogs "Permanent link")

For agents that need different UI components depending on context (e.g., charts for data queries, forms for configuration), resolve the catalog at runtime and store it in session state:

`[](#__codelineno-6-1)async def _prepare_session(self, context, run_request, runner):     [](#__codelineno-6-2)    session = await super()._prepare_session(context, run_request, runner) [](#__codelineno-6-3)    [](#__codelineno-6-4)    # Determine client capabilities from request metadata    [](#__codelineno-6-5)    capabilities = context.message.metadata.get("a2ui_client_capabilities") [](#__codelineno-6-6)    [](#__codelineno-6-7)    # Select the right catalog    [](#__codelineno-6-8)    a2ui_catalog = self.schema_manager.get_selected_catalog(        [](#__codelineno-6-9)        client_ui_capabilities=capabilities    [](#__codelineno-6-10)    )    [](#__codelineno-6-11)    examples = self.schema_manager.load_examples(a2ui_catalog, validate=True) [](#__codelineno-6-12)    [](#__codelineno-6-13)    # Store in session state for tool access    [](#__codelineno-6-14)    await runner.session_service.append_event(        [](#__codelineno-6-15)        session,        [](#__codelineno-6-16)        Event(            [](#__codelineno-6-17)            actions=EventActions(                [](#__codelineno-6-18)                state_delta={                    [](#__codelineno-6-19)                    "system:a2ui_enabled": True,                    [](#__codelineno-6-20)                    "system:a2ui_catalog": a2ui_catalog,                    [](#__codelineno-6-21)                    "system:a2ui_examples": examples,                [](#__codelineno-6-22)                }            [](#__codelineno-6-23)            ),        [](#__codelineno-6-24)        ),    [](#__codelineno-6-25)    )    [](#__codelineno-6-26)    return session`

### Custom catalogs[¶](#custom-catalogs "Permanent link")

You can define your own component catalogs for domain-specific UI:

`[](#__codelineno-7-1)from a2ui.core.schema.manager import CatalogConfig [](#__codelineno-7-2)[](#__codelineno-7-3)schema_manager = A2uiSchemaManager(     [](#__codelineno-7-4)    catalogs=[        [](#__codelineno-7-5)        BasicCatalog.get_config(),        [](#__codelineno-7-6)        CatalogConfig.from_path(            [](#__codelineno-7-7)            name="my_dashboard_catalog",            [](#__codelineno-7-8)            catalog_path="catalogs/dashboard.json",            [](#__codelineno-7-9)            examples_path="catalogs/dashboard_examples",        [](#__codelineno-7-10)        ),    [](#__codelineno-7-11)    ], [](#__codelineno-7-12))`

### Multi-agent orchestration[¶](#multi-agent-orchestration "Permanent link")
