# Agent Identity Auth Manager for ADK[¶](#agent-identity-auth-manager-for-adk "Permanent link")

Supported in ADKPython v1.30.0Preview

The [Google Cloud Agent Identity](https://docs.cloud.google.com/iam/docs/agent-identity-overview) service provides a streamlined, Google-managed solution for managing the complete lifecycle of auth credentials, including storing credential configurations, generating and storing tokens, and auditing access. This approach allows for a secure and simplified agent development experience.

Preview release

The Agent Identity Auth Manager feature is a Preview release. For more information, see the [launch stage descriptions](https://cloud.google.com/products#product-launch-stages).

## Use cases[¶](#use-cases "Permanent link")

-   **Simplified OAuth Flow**: Manage the complete lifecycle of auth credentials without building custom infrastructure.
-   **Secure Exchange and Storage of Tokens**: Securely store credential configurations and exchange tokens.
-   **Audit Logging**: View and audit access to stored credentials.

## Prerequisites[¶](#prerequisites "Permanent link")

-   A [Google Cloud project](https://cloud.google.com/resource-manager/docs/creating-managing-projects)
-   One or more Agent Identity [auth providers](https://cloud.google.com/iam/docs/manage-auth-providers-v2) created in your project
-   The caller identity must have the [`agentidentity.user`](https://docs.cloud.google.com/iam/docs/roles-permissions/agentidentity#agentidentity.user) role or equivalent permissions
-   Authentication configured via [Application Default Credentials](https://docs.cloud.google.com/docs/authentication/application-default-credentials) (`gcloud auth application-default login`)

## Installation[¶](#installation "Permanent link")

Install the `agent-identity` extra package group to download the necessary client libraries.

`[](#__codelineno-0-1)pip install "google-adk[agent-identity]"`

## Use with agent[¶](#use-with-agent "Permanent link")

Follow these steps to use the Agent Identity Auth Manager within ADK:

### Register auth provider[¶](#register-auth-provider "Permanent link")

To enable ADK to determine which `BaseAuthProvider` to use for a given `CustomAuthScheme`, register the `GcpAuthProvider` instance with the `CredentialManager`. This needs to be done only once in the agent code.

`[](#__codelineno-1-1)from google.adk.auth.credential_manager import CredentialManager [](#__codelineno-1-2)from google.adk.integrations.agent_identity import GcpAuthProvider [](#__codelineno-1-3)[](#__codelineno-1-4)CredentialManager.register_auth_provider(GcpAuthProvider())`

### Configure tools[¶](#configure-tools "Permanent link")

Configure the Agent Identity auth provider using a `GcpAuthProviderScheme` object, then pass it to the `auth_scheme` parameter of any supported `Tool` or `Toolset`. The following example shows usage with `McpToolset`, but `GcpAuthProviderScheme` also works with other tools like `AuthenticatedFunctionTool`. See the [GCP Auth sample](https://github.com/google/adk-python/tree/main/src/google/adk/integrations/agent_identity) for a complete example.

`[](#__codelineno-2-1)from google.adk.integrations.agent_identity import GcpAuthProviderScheme [](#__codelineno-2-2)from google.adk.tools.mcp_tool import McpToolset [](#__codelineno-2-3)from google.adk.tools.mcp_tool import StreamableHTTPConnectionParams [](#__codelineno-2-4)[](#__codelineno-2-5)auth_scheme = GcpAuthProviderScheme(     [](#__codelineno-2-6)    # If using the legacy V1 API, the resource name uses 'connectors'    [](#__codelineno-2-7)    # instead of 'authProviders': projects/.../connectors/...    [](#__codelineno-2-8)    name="projects/PROJECT_ID/locations/LOCATION/authProviders/AUTH_PROVIDER_NAME",    [](#__codelineno-2-9)    # continue_uri is only needed for 3-legged OAuth flows. This URI receives    [](#__codelineno-2-10)    # the redirect after user consent and must be hosted by your application.    [](#__codelineno-2-11)    continue_uri=CONTINUE_URI [](#__codelineno-2-12)) [](#__codelineno-2-13)[](#__codelineno-2-14)toolset = McpToolset(     [](#__codelineno-2-15)    connection_params=StreamableHTTPConnectionParams(url="https://YOUR_MCP_SERVER_URL"),    [](#__codelineno-2-16)    auth_scheme=auth_scheme, [](#__codelineno-2-17))`

### Handle OAuth consent[¶](#handle-oauth-consent "Permanent link")

-   **Detecting the Auth Request**: Similar to the existing flow, whenever user consent is required, a `FunctionCall` event named `adk-request-credential` is generated containing the `auth_uri` field. The user app should open the `auth_uri` in a popup window to continue the user consent flow.
-   **Continue URI Handler**:
    -   Once the user completes the OAuth consent flow on the third-party provider's website, the system redirects to the `continue_uri` callback defined earlier in the `GcpAuthProviderScheme`. The agent application service must implement this redirect. To finalize issuance, your handler must submit a POST request to the credentials endpoint: `https://agentidentitycredentials.googleapis.com/v1/{auth_provider_name}/credentials:finalize`.
    -   After credentials are successfully finalized, the web application should resume the agent by sending a FunctionResponse. For a sample implementation, refer to the [sample code](https://docs.cloud.google.com/iam/docs/auth-with-3lo-v2#resume-conversation). Unlike the native user consent flow, no authorization code is required to resume the agent.
    -   For more details, refer to the [sample handler implementation](https://docs.cloud.google.com/iam/docs/auth-with-3lo-v2#validation-endpoint).
-   **Resume the conversation**: Irrespective of the status of the consent flow (successful or unsuccessful), the agent app should resume the agent to complete the conversation turn. The ADK automatically determines whether consent was successfully completed and raise an error if it was not.
