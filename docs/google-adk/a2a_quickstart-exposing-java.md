# Quickstart: Exposing a remote agent via A2A[¶](#quickstart-exposing-a-remote-agent-via-a2a "Permanent link")

Supported in ADKJavaExperimental

This quickstart covers the most common starting point for any developer: **"I have an agent. How do I expose it so that other agents can use my agent via A2A?"**. This is crucial for building complex multi-agent systems where different agents need to collaborate and interact.

## Overview[¶](#overview "Permanent link")

This sample demonstrates how you can expose an ADK agent using Quarkus so that it can be then consumed by another agent using the A2A Protocol.

In Java, you build an A2A server natively by relying on the ADK A2A extension. This uses the Quarkus framework, meaning you just configure your agent directly within your standard Quarkus `@ApplicationScoped` bindings.

`[](#__codelineno-0-1)┌─────────────────┐                             ┌───────────────────────────────┐ [](#__codelineno-0-2)│   Root Agent    │       A2A Protocol          │ A2A-Exposed Check Prime Agent │ [](#__codelineno-0-3)│                 │────────────────────────────▶│       (localhost:9090)        │ [](#__codelineno-0-4)└─────────────────┘                             └───────────────────────────────┘`

## Exposing the Remote Agent with Quarkus[¶](#exposing-the-remote-agent-with-quarkus "Permanent link")

Using Quarkus, you map your agent into an A2A execution endpoint without manually wrangling incoming HTTP JSON-RPC payloads or sessions.

### 1\. Getting the Sample Code[¶](#getting-the-sample-code "Permanent link")

The fastest way to get started is by checking the standalone Quarkus app inside the `contrib/samples/a2a_server` folder within the [**`adk-java`** repo](https://github.com/google/adk-java).

`[](#__codelineno-1-1)cd contrib/samples/a2a_server`

### 2\. How it works[¶](#2-how-it-works "Permanent link")

The core runtime uses a provided `AgentExecutor` which requires you to build a CDI `@Produces` bean configuring your native `BaseAgent`. The Quarkus A2A extension discovers this and wires the endpoints automatically.

A2aExposingSnippet.java

`[](#__codelineno-2-1)import com.google.adk.a2a.executor.AgentExecutorConfig; [](#__codelineno-2-2)import com.google.adk.core.BaseAgent; [](#__codelineno-2-3)import com.google.adk.core.LlmAgent; [](#__codelineno-2-4)import com.google.adk.sessions.InMemorySessionService; [](#__codelineno-2-5)import io.a2a.server.agentexecution.AgentExecutor; [](#__codelineno-2-6)import jakarta.enterprise.context.ApplicationScoped; [](#__codelineno-2-7)import jakarta.enterprise.inject.Produces; [](#__codelineno-2-8)[](#__codelineno-2-9)import com.google.adk.artifacts.InMemoryArtifactService; [](#__codelineno-2-10)[](#__codelineno-2-11)/**  [](#__codelineno-2-12) * Exposing an agent to the A2A network using ADK's Quarkus module. [](#__codelineno-2-13) * By defining an AgentExecutor as a CDI @Produces, the framework [](#__codelineno-2-14) * automatically binds your agent to the A2A endpoint. [](#__codelineno-2-15) */ [](#__codelineno-2-16)@ApplicationScoped [](#__codelineno-2-17)public class A2aExposingSnippet { [](#__codelineno-2-18)    [](#__codelineno-2-19)    @Produces    [](#__codelineno-2-20)    public AgentExecutor agentExecutor() {        [](#__codelineno-2-21)        BaseAgent myRemoteAgent = LlmAgent.builder()            [](#__codelineno-2-22)            .name("prime_agent")            [](#__codelineno-2-23)            .model("gemini-2.5-flash")            [](#__codelineno-2-24)            .instruction("You are an expert in mathematics. Check if numbers are prime.")            [](#__codelineno-2-25)            .build(); [](#__codelineno-2-26)        [](#__codelineno-2-27)        return new com.google.adk.a2a.executor.AgentExecutor.Builder()            [](#__codelineno-2-28)            .agent(myRemoteAgent)            [](#__codelineno-2-29)            .appName("my-adk-a2a-server")            [](#__codelineno-2-30)            .sessionService(new InMemorySessionService())            [](#__codelineno-2-31)            .artifactService(new InMemoryArtifactService())            [](#__codelineno-2-32)            .agentExecutorConfig(AgentExecutorConfig.builder().build())            [](#__codelineno-2-33)            .build();    [](#__codelineno-2-34)    } [](#__codelineno-2-35)}`

The app handles incoming JSON-RPC calls over HTTP mounted on `/a2a/remote/v1/message:send` automatically forwarding parts, history, and contexts directly into your `BaseAgent` flow.

### 3\. Start the Remote A2A Agent server[¶](#start-the-remote-a2a-agent-server "Permanent link")

Within the native ADK structure, you can run the Quarkus dev mode task:

`[](#__codelineno-3-1)./mvnw -f contrib/samples/a2a_server/pom.xml quarkus:dev`

Once executed, Quarkus automatically hosts your A2A compliant REST paths. A manual `curl` allows you to immediately smoke test the payload using native A2A specifications:

`[](#__codelineno-4-1)curl -X POST http://localhost:9090 \   [](#__codelineno-4-2)  -H "Content-Type: application/json" \  [](#__codelineno-4-3)  -d '{        [](#__codelineno-4-4)        "jsonrpc": "2.0",        [](#__codelineno-4-5)        "id": "cli-check",        [](#__codelineno-4-6)        "method": "message/send",        [](#__codelineno-4-7)        "params": {          [](#__codelineno-4-8)          "message": {            [](#__codelineno-4-9)            "kind": "message",            [](#__codelineno-4-10)            "contextId": "cli-demo-context",            [](#__codelineno-4-11)            "messageId": "cli-check-id",            [](#__codelineno-4-12)            "role": "user",            [](#__codelineno-4-13)            "parts": [              [](#__codelineno-4-14)              { "kind": "text", "text": "Is 3 prime?" }            [](#__codelineno-4-15)            ]          [](#__codelineno-4-16)          }        [](#__codelineno-4-17)        }      [](#__codelineno-4-18)      }'`

### 4\. Check that your remote agent is running[¶](#check-that-your-remote-agent-is-running "Permanent link")

A proper agent card is exposed over a standard path representing your instance automatically: [http://localhost:9090/.well-known/agent-card.json](http://localhost:9090/.well-known/agent-card.json)

You should be able to see the name dynamically mirrored from your agent configuration inside the response JSON.
