# Use the Command Line[¶](#use-the-command-line "Permanent link")

Supported in ADKPython v0.1.0TypeScript v0.2.0Go v0.1.0Java v0.1.0

ADK provides an interactive terminal interface for testing your agents. This is useful for quick testing, scripted interactions, and CI/CD pipelines.

![ADK Run](./images/img_f9a50d7d12.png)

## Run an agent[¶](#run-an-agent "Permanent link")

Use the following command to run your agent in the ADK command line interface:

PythonTypeScriptGoJava

`[](#__codelineno-0-1)adk run my_agent`

`[](#__codelineno-1-1)npx @google/adk-devtools run agent.ts`

In Go, the command-line interface is not a standalone `adk` tool. Instead, you embed the launcher directly in your agent's `main.go`. The `full.NewLauncher()` helper bundles the console, web server, and other modes into a single binary, with **console as the default** when no subcommand keyword is given:

main.go

`[](#__codelineno-2-1)import (     [](#__codelineno-2-2)    "google.golang.org/adk/v2/cmd/launcher"    [](#__codelineno-2-3)    "google.golang.org/adk/v2/cmd/launcher/full" [](#__codelineno-2-4)) [](#__codelineno-2-5)[](#__codelineno-2-6)func main() {     [](#__codelineno-2-7)    // ... build your agent and config ...    [](#__codelineno-2-8)    l := full.NewLauncher()    [](#__codelineno-2-9)    if err := l.Execute(ctx, config, os.Args[1:]); err != nil {        [](#__codelineno-2-10)        log.Fatalf("Run failed: %v\n\n%s", err, l.CommandLineSyntax())    [](#__codelineno-2-11)    } [](#__codelineno-2-12)}`

Run the agent in console mode with either of the following commands:

`[](#__codelineno-3-1)go run agent.go           # console is the default sublauncher [](#__codelineno-3-2)go run agent.go console   # or explicitly name the console subcommand`

Create an `AgentCliRunner` class (see [Java Quickstart](../../get-started/java/)) and run:

`[](#__codelineno-4-1)mvn compile exec:java -Dexec.mainClass="com.example.agent.AgentCliRunner"`

This starts an interactive session where you can type queries and see agent responses directly in your terminal.

PythonTypeScriptGoJava

`[](#__codelineno-5-1)Running agent my_agent, type exit to exit. [](#__codelineno-5-2)[user]: What's the weather in New York? [](#__codelineno-5-3)[my_agent]: The weather in New York is sunny with a temperature of 25°C. [](#__codelineno-5-4)[user]: exit`

`[](#__codelineno-6-1)Running agent my_agent, type exit to exit. [](#__codelineno-6-2)[user]: What's the weather in New York? [](#__codelineno-6-3)[my_agent]: The weather in New York is sunny with a temperature of 25°C. [](#__codelineno-6-4)[user]: exit`

`[](#__codelineno-7-1)User -> What's the weather in New York? [](#__codelineno-7-2)[](#__codelineno-7-3)Agent -> The weather in New York is sunny with a temperature of 25°C. [](#__codelineno-7-4)[](#__codelineno-7-5)User ->`

To exit, press **Ctrl+C** or send EOF (**Ctrl+D**).

`[](#__codelineno-8-1)Running agent my_agent, type exit to exit. [](#__codelineno-8-2)[user]: What's the weather in New York? [](#__codelineno-8-3)[my_agent]: The weather in New York is sunny with a temperature of 25°C. [](#__codelineno-8-4)[user]: exit`

## Session options[¶](#session-options "Permanent link")

Python only

The `--save_session`, `--resume`, `--replay`, and `--session_id` options are available in the Python ADK CLI only. The Go console launcher does not support session save/resume/replay via command-line flags. In Go, session persistence is configured in code by providing a persistent `session.Service` implementation (such as `session/database`) to `launcher.Config`.

The `adk run` command includes options for saving, resuming, and replaying sessions.

### Save sessions[¶](#save-sessions "Permanent link")

To save the session when you exit:

`[](#__codelineno-9-1)adk run --save_session path/to/my_agent`

You'll be prompted to enter a session ID, and the session will be saved to `path/to/my_agent/<session_id>.session.json`.

You can also specify the session ID upfront:

`[](#__codelineno-10-1)adk run --save_session --session_id my_session path/to/my_agent`

### Resume sessions[¶](#resume-sessions "Permanent link")

To continue a previously saved session:

`[](#__codelineno-11-1)adk run --resume path/to/my_agent/my_session.session.json path/to/my_agent`

This loads the previous session state and event history, displays it, and allows you to continue the conversation.

### Replay sessions[¶](#replay-sessions "Permanent link")

To replay a session file without interactive input:

`[](#__codelineno-12-1)adk run --replay path/to/input.json path/to/my_agent`

The input file should contain initial state and queries:

`[](#__codelineno-13-1){   [](#__codelineno-13-2)  "state": {"key": "value"},  [](#__codelineno-13-3)  "queries": ["What is 2 + 2?", "What is the capital of France?"] [](#__codelineno-13-4)}`

## Storage options[¶](#storage-options "Permanent link")

Python only

The `--session_service_uri` and `--artifact_service_uri` command-line flags are available in the Python ADK CLI only. In Go, session and artifact services are configured in code when constructing `launcher.Config` — for example, using `session/database` for a persistent database-backed session store, or `artifact/gcsartifact` for Cloud Storage-backed artifacts.

Option

Description

Default

`--session_service_uri`

Custom session storage URI

Per-agent SQLite at `<agents_dir>/<agent>/.adk/session.db`

`--artifact_service_uri`

Custom artifact storage URI

Per-agent directory at `<agents_dir>/<agent>/.adk/artifacts`

`--memory_service_uri`

Custom memory service URI

In-memory

### Example with storage options[¶](#example-with-storage-options "Permanent link")

`[](#__codelineno-14-1)adk run --session_service_uri "sqlite:///my_sessions.db" path/to/my_agent`

## All options[¶](#all-options "Permanent link")

PythonGo

To send a single message and exit instead of starting an interactive session, pass the query as an argument:

`[](#__codelineno-15-1)adk run path/to/my_agent "hello"`

Option

Description

`--save_session`

Save the session to a JSON file on exit

`--session_id`

Session ID to use when saving

`--resume`

Path to a saved session file to resume

`--replay`

Path to an input file for non-interactive replay

`--session_service_uri`

Custom session storage URI

`--artifact_service_uri`

Custom artifact storage URI

`--memory_service_uri`

Custom memory service URI

`--use_local_storage/--no_use_local_storage`

Use the local `.adk` folder when no service URI is set

`--state`

Initial state for the run as a JSON string

`--timeout`

Timeout for a single turn or query, such as `30s` or `5m`

`--in_memory`

Do not persist session data

`--jsonl`

Output structured JSONL instead of human-readable text

`--default_llm_model`

Default model when the agent does not set one

Go flags differ from Python

The Go console launcher does not support `--save_session`, `--resume`, `--replay`, `--session_id`, `--session_service_uri`, or `--artifact_service_uri`. These are Python CLI features. Session and artifact services are configured in Go code via `launcher.Config`.

Flags are passed after the `console` keyword (or directly if `console` is the default):

Flag

Description

Default

`-streaming_mode`

Streaming mode for agent responses (`none`|`sse`)

Auto-detected (TTY → `sse`, pipe → `none`)

`-shutdown-timeout`

Graceful shutdown wait time

`2s`

`-otel_to_cloud`

Export OpenTelemetry data to GCP

`false`

For example, to force non-streaming output:

`[](#__codelineno-16-1)go run agent.go console -streaming_mode none`

Or to force SSE streaming (token-by-token output):

`[](#__codelineno-17-1)go run agent.go -streaming_mode sse`

## Usage telemetry[¶](#usage-telemetry "Permanent link")

The ADK CLI collects anonymous usage telemetry to understand feature adoption, guide development priorities, and improve tool performance. Data collection is OFF by default until you explicitly choose to enable it.

Your telemetry preference is stored locally on your machine in `~/.adk/config.json`. You can manage telemetry data collection at any time through the terminal:

-   **Enable**: `adk telemetry enable`
-   **Disable**: `adk telemetry disable`
-   **Check status**: `adk telemetry status`

You can also manually deactivate telemetry data collection at any time by opening `~/.adk/config.json` and setting the `telemetry` attribute to `false`:

`[](#__codelineno-18-1){   [](#__codelineno-18-2)  "telemetry": false [](#__codelineno-18-3)}`

**What data is collected**

-   **Environment Properties**: Operating system information, runtime language and version, and installed ADK CLI version.
-   **Command Execution Events**: Generic command and subcommand names, flags passed, execution duration, exit codes, and exception types if an error occurs. We also log a sequence number and an ephemeral session ID that is discarded after command execution.

**What data is not collected**

The CLI does not collect sensitive, private, or personal data, specifically:

-   Arguments or parameter values passed to commands or flags, such as agent names, prompt strings, file paths.
-   User credentials, usernames, API keys, OAuth tokens, or secrets.
-   Google Cloud Project IDs or Cloud Account details.
-   Source code files, file contents, or directory paths.
-   Personally Identifiable Information (PII).
